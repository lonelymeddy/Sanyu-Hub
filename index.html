Quick Start Guide

Step-by-step instructions for integrating Meddy API into your application.

1. Determine Base URL

All requests are routed through the single canonical Meddy API base URL. Use the base URL matching your deployment environment:

Canonical Base URL
http://localhost:3000

2. Make your First Catalogue Request

All public catalogue endpoints support RESTful GET requests with JSON responses.

async function loadCatalogue() {
  const res = await fetch('http://localhost:3000/api/movies?country=ug&limit=10');
  const data = await res.json();
  console.log(`Loaded ${data.movies.length} movies out of ${data.total}`);
}

3. Stream Media via API-Managed Proxy Routes

Direct raw media and storage URLs are sanitized and concealed for security and CORS compliance. Applications must use the provided streamUrl or embedUrl properties returned in resource items.

<!-- Stream via HLS / HTML5 Video element -->
<video controls src="http://localhost:3000/api/stream/movie/1"></video>

<!-- Or embed Meddy API player -->
<iframe src="http://localhost:3000/embed?type=movie&id=1" width="100%" height="450" frameborder="0" allowfullscreen></iframe>

Authentication & Security

Understanding public API access controls and secure media delivery.

Public API Access

All public catalogue and stream proxy endpoints (movies, series, live TV, radio, concerts) are accessible without requiring API key headers for standard read operations.

Data Sanitization & Secret Concealment

In accordance with security standards:

  • Internal database IDs, storage bucket names, and provider credentials are stripped from public responses.
  • Direct media URLs hosted on upstream domains (such as storage.swahix.com) are protected and served exclusively via API-managed proxy endpoints (/api/stream-proxy, /api/stream/:type/:id).
  • CORS and Referer header spoofing required by third-party storage streams are handled server-side.

Media Proxy & Stream Delivery

Architecture of API-managed stream proxying and player embedding.

Stream Proxy Architecture

Meddy API provides built-in proxy endpoints for all video streams and radio broadcasts. This guarantees:

  • Zero exposure of third-party bucket credentials or origin domain details.
  • Range-request support (HTTP 206 Partial Content) for video scrubbing and timeline navigation.
  • Domain restrictions (such as Referer: https://swahix.com/ required for Swahix media) are satisfied automatically by Meddy API servers.

Available Proxy Endpoints

Resource Type Endpoint Route Description
Movie Stream GET /api/stream/movie/:id Proxies movie stream by movie ID.
Series Stream GET /api/stream/series/:id Proxies series episode stream by episode ID.
Live TV Stream GET /api/stream/tv/:id Proxies Live TV broadcast channel HLS stream by channel ID.
Radio Stream GET /api/stream/radio/:id Proxies FM radio station audio stream by station ID.
Generic Stream Proxy GET /api/stream-proxy?url=:targetUrl Proxies protected media URL with referer injection.

Countries & Languages API

Regional isolation, language dubbing, and VJ translation support.

Supported Countries

Meddy API strictly enforces regional data isolation between supported markets:

  • ug — Uganda market (Luganda, Lusoga, English dubbing & VJ translated catalogues)
  • ke — Kenya market (Swahix ecosystem, Swahili dubbed content)

Language & Dubbing Distinction

Luganda and Lusoga are maintained as distinct language entries. Swahili dubbed movies from the Swahix folder incorporate specialized translator metadata flags (e.g. hasSwahiliDubbing: true, audioTrack: "Swahili Dubbed").

Search & Discovery API

Global and resource-specific search and filtering operations.

Search query parameters (?search=) can be appended to any resource endpoint (movies, series, concerts) to perform instant keyword filtering across titles, VJ names, genres, and overviews.
